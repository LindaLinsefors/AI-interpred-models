Why each of VPD's name components responds to many character names

agent:1dkced5j, for human:braun and the PD team (task:2394). Red-teamed by agent:vcdey9yh (task:2423). Assumes familiarity with VPD and Explain.

Short answer.

  • At layer 1's attention output, the model writes each character name as its own dense vector. The per-name mean vectors show no tight clusters: 59 directions hold 99% of their variance, and no direction holds more than 4%.
  • A rank-1 component reads one projection of its input. VPD's masks vary components independently of each other, so they penalise harmful individual writes even when the omitted components cancel in aggregate.
  • In every decomposition we built, making components serve fewer names made the model's predictions at name slots worse. The best one we tested reaches 0.86 nats of KL at a median of 3 names per component, and 0.11 nats at 29. VPD's name components serve about 30 names each.
  • So VPD's many-names components are what these representations make easy, and the easy alternatives cost accuracy. We have not shown that no learned decomposition could do better.

1. The setup, in brief

  • The data. A Python program we wrote generates children's stories. Stories introduce characters ("a girl named nadia") and copy their names later. The vocabulary is 1,358 words, 195 of them names.
  • The model. A 2-layer Llama (d_model 192, 6 heads of 32, MLP 768) trained on that corpus. It matches the generator's next-word distribution to a KL of 0.002 nats.
  • The decompositions. VPD on all of its matrices: p-8641051d (the original) and p-95cc9c80 (stronger minimality, p-6c625e77's recipe). The numbers below are for p-95cc9c80 unless marked.
  • The name slot. A position where the generator may write a character's name next: after a full stop or closing quote in narration, after a transitive verb, after "both" and the "and" that follows it. Name slots are 15% of tokens. An excerpt from the generator, with ▮ after each name slot as the generator's own labels mark it:
    once there was a girl named nadia and a boy named paul and a girl named ella .▮ both▮ paul and▮ ella play and love▮ nadia .▮ she rests .▮ the ants take▮ ella .
  • Why it matters for Explain. With every o_proj and down_proj component replaced by its program, name slots carry most of the error: 1.67 nats of KL per name slot for p-8641051d, against 0.015 at ordinary tokens. The components active there each carry part of which name it is. The per-component agents found that a table over names fit them, and the brief steered them away from submitting it.

2. What VPD found at name slots

At h.1.attn.o_proj (192 components), 65 components fire almost only at name slots (≥ 80% of their firing), and which name it is explains almost all of their activation there (median η² 0.99, measured in stories with exactly one character so far). Call a component serving a name when it is active (CI > 0) at half or more of that name's name-slot positions in stories with exactly one character introduced so far. Then each of the 65 serves 30.3 names on average, and each name is served by 10.1 of them on average (10th to 90th percentile 8–12).

Lucius's question: with 192 components for a code that spans about 60 directions, why doesn't VPD tile it so that each component serves fewer than 5 names?

3. When VPD lets a component be left out

A rank-1 component k writes qk = uk (vk·x): it reads one number off its input x, the projection on vk, and writes a fixed vector scaled by it. Its causal importance gk is a learned, context-dependent lower bound on its mask: in training the mask is mk = gk + (1 − gk) rk, with each rk drawn independently in [0, 1] (or chosen adversarially).

Why cancellation doesn't rescue a component

Write ak = (1 − gk) qk for the part of component k's write that its CI leaves open to masking. For a fixed site input and fixed CI, with independent uniform rk, the expected squared error the masks put into the layer's output is exactly

E‖Σk (1 − rk) ak‖² = ¼ ‖Σk ak‖² + (1/12) Σk ‖ak‖²

The first term vanishes if the low-CI components cancel each other. The second doesn't: every component left open adds its own energy. So a small error under independent masks bounds the total energy of the components left open, at no more than 12 times that error. Low CI permits independent perturbations of the component's own write; their effect must fit the tolerated local and output error.

The size of the write is ‖qk‖ = ‖uk‖ |vk·x|. So which names a component can leave alone depends on how its read direction lines up with the names' vectors.

4. A two-dimensional picture

Six names whose vectors spread over a plane, and a read direction v you can turn. The bars show each name's projection; a name counts as read strongly when it is at least 0.25 for these unit vectors, an illustrative threshold:

Counting gives one exact constraint. With one rule for "component serves name" (section 2's), every (component, name) pair is counted once from each side:

mean names per component × number of components = mean components per name × number of names

VPD's 65 name components satisfy it: 30.3 × 65 = 10.1 × 195. With 192 components and 195 names, an average below 5 names per component means an average below about 5 components per name. Both averages fall together. The question is whether so few components per name can still write each name faithfully.

Building a name versus reading a name

"192 components for 60 directions leaves room to spare" is right for building each name's vector from a few parts: 195 names could each be one atom. But a rank-1 component doesn't choose when to contribute; it reads by projection. A component whose write vector helps build nadia's vector reads with its own direction v, and that direction also projects onto every name not perpendicular to it.

6. Decompositions built by hand

Any set of read directions spanning the name space gives an exact rank-1 decomposition of h.1.attn.o_proj there, with write vectors from the dual frame. We built four:

  • the 60 principal directions holding 99% of the names' variance (fit rows), then a varimax rotation of them, then the 60 dual reads of 60 basis names (each basis name read by exactly one component);
  • the same basis construction on all 192 directions the names span numerically (192 basis names, basis condition number about 1.3 × 10⁴). This tests the point that low-variance directions can carry selectivity.

At every name slot we kept the m components with the largest write on that input, dropped the rest, and ran the model. The test's scope, which matters when reading it:

  • It edits only h.1.attn.o_proj, only at name slots. The mean input over name slots, and everything outside the name space, are always kept for free.
  • It drops components once, as a hard ablation. VPD's losses use many independent masks.
  • Keeping the largest writes is a reasonable rule, but it is not the subset with the smallest KL.

7. What this does and doesn't show

  • Shown: at this site the model writes names as a dense code, with no tight clusters apparent in the pairwise cosines. The VPD, random and varimax directions in the read-profile chart all have broad overlap. In all four hand-built decompositions, fewer names per component cost KL at name slots: about 0.9 nats or more at a median of 3 names per component.
  • Not shown: that a learned decomposition can't do better. We didn't optimise 192 read and write directions for selectivity under VPD's own losses. The 192-d basis frame beat the 60-d frames by a wide margin, which is a reminder that the easy constructions aren't the limit.
  • Where names are sparse: in token-index space, where each name is its own row of the embedding table. That doesn't automatically give one component per name to a matrix that reads the resulting dense vectors.
  • For Explain: a fitted name table worked where simple rules didn't. The agents tested gender, length, spelling, popularity and token id, and none predicted the per-name weights. One program per co-firing group can share one table instead of repeating it per component. In p-8641051d's group round, the 39-member name group's median CVE rose from 0.07 to 0.985. The whole group round moved the joint KL from 0.317 to 0.199, and the name-slot KL from 1.67 to 1.08.
