How tiny recurrent networks do their jobs: two solved, one not

Three small networks from ARC's AlgZoo, explained neuron by neuron where we could. Every number on this page is printed by a script in code/, run on fresh random inputs. The exceptions are labelled where they appear. Assumes familiarity with neural networks; no other background is needed.

In short
  • Median of 10 numbers, 2 neurons, 8 weights. The network does not compute a median. It keeps one signed running number: a leaky running sum that is hard to push across zero. The output is about the mean of the inputs. A one-line rule reproduces the network's output almost exactly: RMSE 0.0045 between the two, while the network's output has a standard deviation of 0.32.
  • Position of the second-largest of 3 numbers, 3 neurons, 21 weights. On 74% of inputs it runs two comparators. On 20% every neuron is silent and every output is exactly 0, so the answer comes from argmax's habit of picking the first position on a tie. Those silent inputs cause 68% of its errors. A 12-line rule agrees with the network on 99.8% of inputs.
  • Position of the median of 5 numbers, 16 neurons, 352 weights: not cracked. AI research agents found true pieces: earlier inputs stored in the hidden state, and neurons that compare each new input with earlier ones. But nobody assembled the pieces into an account that predicts what the network does when its hidden state is edited.

The setting

Source
AlgZoo, a public set of small networks released by the Alignment Research Center (ARC) as interpretability challenges, each under 1,500 parameters. Checkpoint names give the task, the hidden size and the sequence length: median_2_10 has 2 hidden neurons and reads 10 numbers. We use median_2_10 seed 0, 2nd_argmax_3_3 seed 1 and argmedian_16_5 seed 0.
Architecture
One-layer ReLU RNN with no biases. It reads one number per step:
ht = relu(Wih·xt + Whh·ht−1), with h0 = 0; the output is Wout·hT after the last step.
Inputs
Independent standard normal numbers.
How the explanations were found
AI research agents (Claude models) had the weights and a Python sandbox. One agent per network wrote the account. For this page we turned each account into a replacement rule and compared it with the network on millions of fresh inputs.

No biases means the networks are positively homogeneous: scaling every input by λ > 0 scales every neuron by λ. Section 2 relies on this.

1. Median of 10 numbers: one signed number in two neurons explained

Task. Read 10 numbers, output their median (trained with squared error). Size. 2 neurons, 8 weights. We call the neurons p and n, for the positive and negative parts of the number they store.

The mechanism

Neuron p is driven by +0.335·x and neuron n by −0.333·x. Each excites itself (≈0.98) and strongly inhibits the other (≈−3.5). So at most one of them is on at a time. Together they store one signed number s: p holds its positive part and n its negative part. Measured in input units, s = p/0.335 − n/0.333. Each step updates it as:

s = 0
for x in inputs:
    s = median(x + 0.98*s,  0,  x + 3.5*s)   # middle value of the three
output = 0.114 * s

Evidence that this is the whole mechanism
  • The rule against the network on 1,000,000 fresh sequences: RMSE 0.0045 between their outputs. It leaves 0.02% of the variance of the network's output unexplained.
  • The rule also predicts what happens under an intervention. At a random step we overwrote the network's hidden state with the state another sequence had at that step, then let both the network and the rule run on. The rule carried over only the single number s. Their outputs differed by RMSE 0.0027, while the swap itself moved the output by RMSE 0.335.
  • The two neurons are never both on. That holds on all 10,000,000 (sequence, step) pairs we checked, and it follows from the weights. With n = 0 and p = u, both pre-activations would have to be positive, which needs x < −10.5u and x > −2.9u at once. The mirror case is the same. So the 2-neuron network is exactly a 1-D recurrence.
  • The rule averages the two neurons' nearly mirror-image weights (0.979 and 0.977 become 0.98; 3.49 and 3.58 become 3.5). That averaging is the only approximation.
  • Why the update is a median: with s > 0 (only p on), the new pre-activations are 0.335·(x + 0.977·s) for p and −0.333·(x + 3.51·s) for n, so ReLU keeps whichever is positive, or neither. That is the middle value of x + 0.98s, 0 and x + 3.5s.
  • The output layer reads 0.341·p − 0.342·n, which is 0.114·s in either sign.

2. Second-largest of 3 numbers: two comparators and a dead zone explained

Task. Read 3 numbers x1, x2, x3 and output which position holds the second-largest. With three numbers that is the median. Size. 3 neurons, called a, b and c, and 21 weights. Positions are numbered 1, 2, 3. Accuracy. 90.8%.

The mechanism, region by region

We first flip all signs if needed so that x1 > 0. The task is unchanged by this, and negating all inputs changes only 0.17% of the network's predictions. The ratio r = x2 / x1 then decides which of three regions an input falls in:

B0.938 ≤ r < 6.14: roughly, x2 > x1 > 020.9%67.6%73.8%Dead zone. On 95% of B all three neurons are off at step 3, so all outputs are exactly 0. argmax breaks the tie toward position 1, which happens to be right 68% of the time here.
Fr ≥ 6.14: x1 is tiny next to x25.2%76.2%13.3%Aliasing. After step 2 the state is the same as for the different input (−x1, x2 − 7.08·x1, x3) from region M. The network answers for that input instead.

The whole network, as a rule (from code/second_argmax_3_3.py):

def rule(x1, x2, x3):
    if x1 < 0: x1, x2, x3 = -x1, -x2, -x3          # mirror symmetry
    r = x2 / x1
    if r < 0.938:                                   # region M: two comparators
        if x3 > 1.011*x1 + 0.017*x2: return 1
        if x3 < 1.085*x2 + 0.011*x1: return 2
        return 3
    if r < 6.14:                                    # region B: dead zone, all logits 0
        return 1                                    # argmax tie-break picks the first position
    if x3 < -1.124*x1 + 0.017*x2: return 1          # region F: answers for the aliased input
    if x3 >  1.082*x2 - 7.67*x1:  return 2
    return 3

This rule agrees with the network on 99.81% of 2,000,000 fresh inputs (99.82% in M, 100% in B, 98.9% in F).

Step by step: what each neuron holds

For x1 > 0, writing s = 3.84 for the input weight:

  • Step 1: split x1 by sign. a = s·relu(x1) and c = s·relu(−x1). Neuron b gets almost no input (weight 0.00009).
  • Step 2: store the size of x1 and test where x2 sits. b = 5.39·s·x1. Neuron a = s·relu(x2 − 0.938·x1) fires when x2 is above about x1. Neuron c = s·relu(6.14·x1 − x2) fires when x2 is below 6.14·x1: a large weight from a to c moves its threshold out from x1 to 6.14·x1. These two thresholds create the regions. In M only c is on, in B both are on, and in F only a is on.
  • Step 3 in region M: the active neuron switches from c to a. Now c is off (except when x3 < −38·x1, which is rare). Neuron b = s·(5.05·x1 − 5.39·x2) tracks the gap between x1 and x2. Neuron a = s·(x3 + 4.73·x1 − 6.15·x2) holds x3 shifted by a fixed mix of x1 and x2.
  • Readout: a ratio test. Neurons a and c have nearly equal output weights, so the output sees only q = a + c and b. The answer is position 2 if q/b < 0.938, position 1 if q/b > 1.137, and position 3 in between. Replacing the output layer with this bare ratio test keeps 99.4% of predictions.
  • Why the ratio test is two comparators in M. The thresholds almost cancel one input each. a − 1.137·b = s·(x3 − 1.01·x1 − 0.02·x2), which compares x3 with x1, because 1.137 × 5.39 = 6.13 nearly matches the 6.15 in a. And a − 0.938·b = s·(x3 − 1.09·x2 − 0.01·x1), which compares x3 with x2, because 0.938 × 5.05 = 4.74 nearly matches the 4.73.

Why B goes silent. In B, a + c stays at about 5.2·s·x1 whatever x2 is. Neuron b's step-3 input is 5.39·a − 5.21·b + 5.41·c, and these terms cancel to about −0.011·s·x1, just below zero. So b is off. Neurons a and c receive strong inhibition from b and strong excitation from each other; the inhibition wins by a wide margin (median input about −19·s·x1). They switch on only when x3 lies far beyond x2, in 5% of B; then the outputs are no longer all zero, which is why the hatching in panel (b) has gaps.

A knife edge: shrinking one weight by 0.05% costs 10 points of accuracy

Neuron b's silence in region B rests on a cancellation with a margin of only 0.04%. Its step-3 input is −0.00038 times the size of its self-inhibition term (median over B). Scaling that single recurrent weight, from b to itself (−5.207), by a small factor:

Accuracy66.7%79.0%80.4%80.6%90.8%90.8%90.7%88.7%70.8%

The effect is lopsided. Shrinking the weight's size by 0.05% lets b switch on in B while a and c stay off. The ratio q/b is then 0, so the network answers position 2 there, the least likely right answer. Growing the weight keeps B silent; it only moves the comparator boundaries in M, which costs 2 points at 0.3%.

The 90.8% accuracy depends on how ties are broken

On 19.9% of all inputs the three outputs are exactly 0.0. That share is the same in 32-bit arithmetic, where predictions agree with 64-bit on 99.9999% of inputs. The network is completely uncertain on these inputs. Its reported accuracy holds only because argmax in numpy and PyTorch returns the first maximal position. With random tie-breaking it would score 83.8%. If ties counted as wrong it would score 77.1%. Errors on these all-zero inputs are 67.5% of all its errors.

Checking the aliasing claim

For every input in region F we built the alias input (−x1, x2 − 7.08·x1, x3) and ran the network on it. The network's prediction on the alias matches its prediction on the original for 99.94% of F inputs. The alias keeps x1 and x2 in the right order but moves their values, which explains F's two error bands in panel (c).

What we do not know, and how these accounts were tested
  • Why training produced the dead zone. One hypothesis: step 3 needs the large cross-weights between a and c to build the comparators, and the same weights, reused at step 2, create the band. This is untested. The agent tried retraining the architecture from scratch with its own recipe (Adam, 30,000 steps, 10 seeds), which differs from ARC's. It reached only 55–64% accuracy, so it cannot tell us whether training tends to find the dead zone. This result is from the agent's analysis; our scripts do not rerun it.
  • Why the comparator on the x2 side is 8.5% off (1.085·x2) while the x1 side is accurate. We can name the weights responsible but not the training pressure.
  • How strictly this account was tested. We checked it on unedited inputs, plus the alias substitution and the weight perturbation above. We did not test whether it predicts the effect of editing individual neurons. Section 3 holds the 5-input network to that stricter standard, so the comparison is not like for like.

3. Median position of 5 numbers: a network we could not explain not cracked

Task. Read 5 numbers and output the position of their median. Size. 16 neurons, 352 weights. Accuracy. 98.3% (chance is 20%). ARC has not published its mechanism.

What was tried. AI research agents worked on it in 7 rounds, 35 working sessions in all. In each round four agents worked in parallel from the best account so far, and a fifth merged their results. The goal was an account that predicts the network's answer not only on normal inputs but also when part of its hidden state is replaced by the value it would have on a different input sequence. The baseline account is the plain statement "the network outputs the true median position".

True pieces they found. We confirmed these from the weights with code/argmedian_16_5_checks.py:

  • After step 4, five rows of Whh each read one earlier input from the hidden state, almost linearly: x1, x2, x3, and x4 twice with opposite signs (R² ≥ 0.997 for a linear fit).
  • The same few neurons compare each new input with earlier ones. After step 4, four neurons closely fit relu(x1 − x4), relu(x2 − x4), relu(x3 − x4) and relu(x4 − x3), each scaled by about 11. After step 5, five fit relu(x1 − x5), relu(x2 − x5), relu(x3 − x5), relu(x4 − x5) and relu(x5 − x4). The residuals are 1–5% of each neuron's standard deviation.

What went wrong. These pieces never became an account that predicts edits. The numbers below come from the agents' runs, not from our scripts.

  • Whole-state swaps. When the entire hidden state after one step is replaced by its value from another input, the baseline account predicts the network's answer 29% of the time (averaged over the five steps). The only gain came from the most trivial fact: the state after step 1 depends only on x1, so swaps at step 1 become fully predictable. That lifted the average to 40%. Nothing about the later steps improved it.
  • Single-direction edits. Accounts that used the stored inputs predicted the answer after an edit of one stored input only about half the time (48%, and 52% after a search for better directions). Editing one stored input also changes other neurons' inputs at the next step, so the edited state is unlike any the network sees on real inputs.
  • The agents judged that describing all 16 neurons at step 4 and then the final step would be too long to count as an explanation, and did not attempt it.
Why this failure is worth showing
  • Small is not the same as easy. 352 weights are only about 17 times more than the 21-weight network above. But here the information is spread across many neurons, while each of the solved networks has a few linear regions with one to three nameable quantities each.
  • Finding true local facts is not explaining. Every piece above is correct. None of them, alone or together, predicts what the network does when part of its state is changed.
  • Pressure to score well invites shortcuts. In one round an agent made its account score better by exploiting a loophole in how claims were checked, not by explaining more, and said so in its own notes. The loophole was closed. The honest result is the gain from 29% to 40% above.
